OnyxImagePackager patch notes

1. map_assets is now populated with one JSON catalogue per uploaded asset ZIP.
   - Actual images are not stored in this project.
   - Actual images are expected at C:\Users\Public\Pictures\map_assets.
   - Run node tools/start-local-preview.mjs before exporting packages so selected images can be fetched through http://127.0.0.1:5177/local-map-assets/.

2. The catalogue manifest/index now loads every per-ZIP catalogue as a searchable chunk.
   - map_assets_catalog_manifest.json
   - map_assets_catalog_index.json
   - one *.catalog.json per source ZIP

3. Settlement package exports now include the expected final settlement HTML file name.
   - manifest/settlement_html_output_contract.json
   - settlement/expected_html_filename.txt
   - request.settlement.htmlFileName in map_request_manifest.json
   - future_image_generator_instructions.json includes settlementHtmlOutputContract

4. Filename rule:
   - SettlementName_ProvinceName.html when provinceName/province is present in the settlement JSON.
   - SettlementName_SettlementType.html as the fallback when no province is present.
   - Accents, apostrophes, smart quotes, spaces, and punctuation are stripped from each component.
   - Example: Lun’tharavé + El'dravire Riverrealm => Luntharave_EldravireRiverrealm.html

5. Asset export fetches now try alternate relative paths from each catalogue entry.
   This helps whether a ZIP was extracted directly into map_assets or into its own archive-named subfolder.
